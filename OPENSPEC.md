# OpenSpec: какие команды когда звать

OpenSpec инициализирован в этом репозитории (схема `spec-driven`, артефакты пишутся по-русски —
см. `openspec/config.yaml`). Структурные заголовки и ключевые слова `SHALL` / `MUST` остаются английскими.

## Порядок работы над изменением

Слэш-команды вызываются в Claude Code, по одной на стадию. Каждая стадия заканчивается артефактом.

| Стадия | Команда | Что делает | Признак, что пора дальше |
| --- | --- | --- | --- |
| 1. Подумать | `/opsx:explore <идея>` | Обсуждение и разведка по коду. Код не пишется. | Понятно, что именно менять |
| 2. Спланировать | `/opsx:propose "<идея>"` | Создаёт change: `proposal.md`, `design.md`, `tasks.md`, дельта-спеку `specs/<capability>/spec.md`. Код не трогает. | Артефакты созданы и прочитаны тобой |
| 3. Поправить план | `/opsx:update <change>` | Правит уже созданные артефакты плана, держит их согласованными. | План соответствует задумке |
| 4. Реализовать | `/opsx:apply <change>` | Выполняет задачи из `tasks.md`. Здесь пишется код. | Все задачи в `tasks.md` отмечены |
| 5. Перенести спеки | `/opsx:sync <change>` | Вливает дельта-спеки изменения в основные `openspec/specs/`. | `openspec list --specs` показывает обновлённую спеку |
| 6. Закрыть | `/opsx:archive <change>` | Переносит change в `openspec/changes/archive/`. | `openspec list` больше не показывает изменение |

Стадии 2 и 4 разделены намеренно: `/opsx:propose` не начинает реализацию даже если просьба
звучала как «сделай». Чтобы начать код, вызови `/opsx:apply` отдельным сообщением.

## CLI: посмотреть и проверить

Эти команды безопасны, ничего не меняют, зови в любой момент.

| Команда | Когда |
| --- | --- |
| `openspec list` | Какие изменения сейчас в работе |
| `openspec list --specs` | Какие возможности уже описаны спеками |
| `openspec show <имя>` | Прочитать конкретный change или спеку |
| `openspec status --change <имя>` | Какой артефакт изменения следующий по очереди |
| `openspec validate` | Проверить, что изменения и спеки корректны по структуре |
| `openspec view` | Интерактивный дашборд по спекам и изменениям |
| `openspec doctor` | Проверить, что корень OpenSpec виден и связи целы |

## Обслуживание

| Команда | Когда |
| --- | --- |
| `openspec update` | После обновления CLI — перегенерировать инструкции и скиллы в `.claude/` |
| `openspec config profile` | Добавить остальные workflow: `new`, `continue`, `ff`, `bulk-archive`, `verify`, `onboard` |
| `openspec archive <имя>` | Архивация изменения из терминала, без Claude Code |

## Где что лежит

```
openspec/
  config.yaml          схема, язык артефактов, правила по артефактам
  specs/               текущие спеки: что система делает сейчас
  changes/             активные изменения
  changes/archive/     завершённые изменения
.claude/
  commands/opsx/       шесть слэш-команд
  skills/openspec-*/   скиллы, которые эти команды используют
```

Файлы в `.claude/` и инструкции внутри них генерируются `openspec update` — правки в них
перезаписываются. Свои правила проекта пиши в `openspec/config.yaml` (секции `rules` и `operations`).
