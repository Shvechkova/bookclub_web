# Кабанья Читальня — сайт клуба

Сайт IT-книжного клуба: что читаем, когда встреча, что уже прошло и что клуб
произвёл. Версия только для чтения — входа для участников нет, данные правятся
в файле.

## Как запустить

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -e ".[dev]"   # Linux/macOS: .venv/bin/python

.venv/Scripts/python -m uvicorn app.web.asgi:app --reload
```

Открыть http://127.0.0.1:8000

Рабочий режим — та же команда без `--reload`:

```bash
.venv/Scripts/python -m uvicorn app.web.asgi:app --host 0.0.0.0 --port 8000
```

Путь к данным переопределяется переменной `CLUB_DATA`, к словарю — `CLUB_GLOSSARY`
(по умолчанию `glossary.yaml` рядом с данными).

## Docker

Без Python на машине — в контейнере.

```bash
docker compose up --build
```

Открыть http://127.0.0.1:8737 — порт нарочно необычный, чтобы не спорить с другими проектами. Занят и он — `PORT=8080 docker compose up --build`.

Папка `data/` подключается в контейнер с диска, только для чтения.
Поэтому после правки `club.yaml` хватает перезапуска, пересобирать не нужно:

```bash
docker compose restart web
```

Данные читаются при старте, так что без перезапуска правка не видна.

Остановить:

```bash
docker compose down
```

## Выгрузка в статику

```bash
PYTHONPATH=. .venv/Scripts/python -m app.web.export public
```

Кладёт сайт в `public/`: каждый адрес — папка с `index.html`, рядом `static/`.
Отдаётся любым статическим хостингом.

Посмотреть выгрузку:

```bash
cd public && python -m http.server 8090
```

Если сайт живёт не в корне домена, а в папке — как страница проекта на GitHub
Pages, — префикс задаётся переменной `SITE_BASE`, иначе абсолютные ссылки уедут
в корень чужого сайта:

```bash
MSYS_NO_PATHCONV=1 SITE_BASE=/bookclub_web python -m app.web.export public
```

`MSYS_NO_PATHCONV=1` нужен только в Git Bash на Windows — см. `PITFALLS.md`.

`SITE_URL` задаёт схему и домен — то, чего не собрать из относительных ссылок:
канонический адрес страницы, карточку для пересылки в телеграм и карту сайта.

```bash
MSYS_NO_PATHCONV=1 SITE_BASE=/bookclub_web SITE_URL=https://shvechkova.github.io \
  python -m app.web.export public
```

С ней рядом со страницами появляются `sitemap.xml` и `robots.txt`. Без неё их
нет, и на страницах нет канонических адресов и Open Graph: адрес, собранный из
заголовков запроса, врёт за прокси и на статике, а неверный канонический адрес
уводит поисковик вернее, чем его отсутствие.

Кроме страниц, выгрузка кладёт `404.html` (GitHub Pages отдаёт его на любой
неизвестный адрес; закрыт от индекса), `manifest.webmanifest` и `favicon.ico` в
корень. Канонические адреса и карта сайта — со слешем на конце (`/history/`):
так статика отвечает без переадресации.

### Подтверждение прав в Яндекс.Вебмастере и Google Search Console

Коды подтверждения задаются переменными окружения; пустая — тега нет:

| Переменная | Мета-тег |
|---|---|
| `YANDEX_VERIFICATION` | `<meta name="yandex-verification" content="…">` |
| `GOOGLE_SITE_VERIFICATION` | `<meta name="google-site-verification" content="…">` |

Значение — только код из атрибута `content`, который выдаёт Вебмастер или
Search Console при выборе способа «Мета-тег». При выкатке берутся одноимённые
переменные репозитория (**Settings → Secrets and variables → Actions →
Variables**); после их добавления перезапустите выкатку (**Actions → Сайт
клуба на GitHub Pages → Run workflow**) и только потом жмите «Проверить».
Затем добавьте в Вебмастере и Search Console карту сайта
`https://<домен>/sitemap.xml`. Без своего домена `robots.txt` лежит не в корне
`shvechkova.github.io`, и поисковики его не читают — карту в этом случае
добавляют только вручную.

## Выкатка на GitHub Pages

`.github/workflows/pages.yml` собирает и публикует сайт при каждом push в `main`:
ставит зависимости, прогоняет тесты и выгружает сайт. Перед первой выкаткой в настройках репозитория нужно включить
**Settings → Pages → Source: GitHub Actions**.

Свой домен подключается в двух местах, и имя в них должно совпадать:

1. **Settings → Pages → Custom domain** — домен, плюс галочка Enforce HTTPS,
   когда GitHub выпустит сертификат. У регистратора — запись `CNAME` на
   `shvechkova.github.io` для поддомена или четыре `A`-записи GitHub для
   корня домена.
2. **Settings → Secrets and variables → Actions → Variables** — переменная
   `SITE_DOMAIN`, тот же домен без `https://`.

С доменом сайт собирается в корень `https://<домен>`. Без переменной — в папку
`/<имя репозитория>` на `shvechkova.github.io`. Файл `CNAME` в выгрузку класть
не нужно: при выкатке через Actions GitHub берёт домен из настроек, а не из
файла.

## Тесты

```bash
.venv/Scripts/python -m pytest
```

Проверка вёрстки на узком экране поднимает Chromium через Playwright:

```bash
.venv/Scripts/python -m playwright install chromium
```

## Что где лежит

```
app/core/     ядро: модель клуба и вычисления. Без HTTP, шаблонов и YAML
app/data/     чтение файла данных и проверка инвариантов
app/web/      маршруты, шаблоны, оформление
data/         данные клуба (club.yaml) и описание формата
tests/        тесты; ядро проверяется напрямую, страницы — через клиент
```

Граница «ядро — рендер» проведена намеренно: поверх ядра позже лягут генерация
картинок-анонсов и телеграм-бот, и переписывать ради них рендер не придётся.
Проверка границы — в `tests/test_boundaries.py`: ядро не должно тянуть ни
веб-фреймворк, ни шаблоны, ни YAML.

## Данные клуба

Формат описан в [`data/README.md`](data/README.md). Коротко: три раздела —
`club`, `books`, `meetings`. Книга хранит оглавление, встреча перечисляет
разобранные главы с отметкой «закрыли / перенесли / ещё не разбирали».

Вычисляемое в данных не хранится: номер встречи, пройденные главы, число встреч
по книге, темп и каталог тем выводятся из встреч каждый раз заново.

Словарь понятий — отдельный файл `data/glossary.yaml`: короткие определения для
страницы «Словарь» и подсказок у тем встреч. Длинные статьи остаются в
репозитории конспектов.

Анонсы, итоги и конспекты глав в данные переносит проектный скилл
[`club-ingest`](.claude/skills/club-ingest/SKILL.md).

Конспекты остаются в [Shvechkova/summary](https://github.com/Shvechkova/summary):
сайт хранит адреса, а не тексты.
