# Файл данных клуба

Данные клуба лежат одним файлом YAML. Рабочий файл — `club.yaml`, образец со всеми
возможностями — `club.example.yaml`. Файл правится руками; при загрузке он
проверяется, и на неверных данных сайт не поднимается.

## Ловушка при ручной правке

Значение, внутри которого есть двоеточие с пробелом, YAML принимает за вложенный
словарь и падает с `mapping values are not allowed here`. Такие строки нужно
заключать в кавычки:

```yaml
close_note: "Бросили на второй главе: язык оказался неподъёмным."
```

## Три раздела

```yaml
club:     { ... }   # сам клуб: как называется, где и когда собирается
books:    [ ... ]   # книги: оглавление, состояние, конспекты
meetings: [ ... ]   # встречи: даты, разобранные главы, итоги
```

## club

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `name` | да | Название клуба |
| `descriptor` | да | Подпись под названием, «IT книжный клуб» |
| `about` | да | Абзац для раздела «О клубе» |
| `place` | да | Где собираемся |
| `slot` | да | Постоянный слот: «среда, раз в две недели» |
| `time` | да | Время начала |
| `duration` | да | Сколько идёт встреча |
| `telegram` | нет | Адрес чата. Не задан — ссылки в шапке нет |
| `marquee` | нет | Тексты бегущих строк, до двух: верхняя и нижняя |
| `rules` | да | Договор клуба списком |
| `topic_notes` | нет | Адреса конспектов понятий: `название: адрес` |

`topic_notes` — это карта адресов, а не список понятий. Сам каталог понятий
собирается из тем встреч; здесь только куда вести ссылку. Ключ, который не
встречается ни на одной встрече, считается ошибкой данных — иначе опечатка
молча оставит понятие без ссылки.

## books

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `id` | да | Идентификатор, попадает в адрес страницы |
| `number` | да | Номер книги. Задаёт порядок, в том числе у книг без встреч |
| `title`, `author` | да | Название и автор |
| `status` | да | `voting`, `queued`, `reading`, `closed`, `dropped` |
| `chapters` | да | Оглавление по порядку. Номер главы — её позиция, с единицы |
| `taken_chapters` | нет | Номера глав, взятых в чтение. Не задано — взяты все |
| `period` | нет | «весна 2025». Для книг, встречи по которым не записаны |
| `notes_url` | нет | Конспект книги целиком |
| `close_note` | нет | Чем закончили. У закрытых и дропнутых |
| `takeaways` | нет | Выводы клуба списком |

У главы: `title` и необязательный `notes_url`.

`taken_chapters` нужен для выборочного чтения: «читаем не книгу, а вот эти
главы». Прогресс считается от взятых глав, а не от всего оглавления.

## meetings

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `id` | да | Идентификатор, попадает в адрес страницы |
| `date` | да | `ГГГГ-ММ-ДД` |
| `time`, `place` | нет | Не заданы — берутся из `club` |
| `host` | нет | Ведущий |
| `book` | нет | `id` книги. Есть — у встречи книжная часть |
| `chapters` | нет | Разобранные главы: `{number, outcome}` |
| `format` | нет | Формат второго часа: `{name, note}` |
| `title` | если нет `book` | Собственное название встречи |
| `announce` | нет | Пункты анонса |
| `outcome` | нет | Итоги: `agreed`, `argued`, `taken`, `quote: {text, chapter}` |
| `topics` | нет | Темы встречи. Из них собирается каталог понятий |
| `links` | нет | Ссылки: `{title, url}` |

`outcome` у главы встречи — `closed` (закрыли), `carried` (перенесли) или
`planned` (ещё не разбирали). Не указан — значит `planned`: так пишется план
предстоящей встречи.
Перенесённая глава пройденной не считается, пока её не закроют на другой встрече.
Перечень глав не обязан идти подряд.

## Что проверяется при загрузке

- В состоянии `reading` — не больше одной книги.
- `status` — из известного набора.
- Даты встреч разбираются как даты, идентификаторы не повторяются.
- У встречи без `book` есть `title`.
- `chapters` встречи указаны только вместе с `book` и ссылаются на существующие
  главы этой книги.
- `taken_chapters` ссылаются на существующие главы.
- Ключи `topic_notes` встречаются хотя бы на одной встрече.
