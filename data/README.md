# Файл данных клуба

Данные клуба лежат одним файлом YAML. Рабочий файл — `club.yaml`, образец со всеми
возможностями — `club.example.yaml`. Файл правится руками; при загрузке он
проверяется, и на неверных данных сайт не поднимается.

## Ловушка при ручной правке

Значение, внутри которого есть двоеточие с пробелом, YAML принимает за вложенный
словарь и падает с `mapping values are not allowed here`. Такие строки нужно
заключать в кавычки:

```yaml
close_note: "Бросили на второй главе: язык оказался неподъёмным."
```

## Три раздела

```yaml
club:     { ... }   # сам клуб: как называется, где и когда собирается
books:    [ ... ]   # книги: оглавление, состояние, конспекты
meetings: [ ... ]   # встречи: даты, разобранные главы, итоги
```

## club

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `name` | да | Название клуба |
| `descriptor` | да | Подпись под названием, «IT книжный клуб» |
| `tagline` | нет | Чем клуб является, с городом. Идёт в заголовок главной и в карточку пересылки. Не задан — берётся `descriptor` |
| `since` | нет | Год основания числом, `2023`. Стоит в строке заставки главной: «IT-книжный клуб в Самаре · с 2023» |
| `manifesto` | нет | Фраза-манифест — крупный заголовок заставки главной. Перевод строки в многострочной строке YAML задаёт, где заголовок делится на строки. Не задана — заголовком идёт `tagline` |
| `about` | да | Лид раздела «О клубе». Список абзацев, не строка |
| `routine` | нет | «Как проходит встреча» — список пунктов. Показывается, только если не заданы `rules` |
| `about_title` | нет | Заголовок страницы «О клубе», «Первый IT-книжный клуб Самары». Не задан — заголовком идёт «О клубе» |
| `about_hand` | нет | Рукописная строка под заголовком «О клубе». Перевод строки в многострочной строке YAML делит её на строки |
| `facts` | нет | Факты о клубе карточками: список `{label, text}`. Заданы — заменяют абзацы `about` после первого, первый остаётся лидом |
| `rules` | нет | «Как проходит встреча» карточками: список `{label, text}`. Заданы — стоят вместо `routine` |
| `place` | да | Где собираемся, по частям — см. ниже |
| `slot` | да | Постоянный слот: «среда, раз в две недели» |
| `time` | да | Время начала |
| `duration_minutes` | да | Сколько идёт встреча, числом минут |
| `timezone` | да | Часовой пояс клуба, `Europe/Samara`. Нужен ссылке «в календарь» |
| `terms` | нет | Условия прихода списком строк: «вход свободный», «не прочитал — всё равно приходи» |
| `telegram` | нет | Адрес чата клуба: ссылка «чат клуба» в подвале и кнопка «Чат клуба» на «О клубе» с пометкой «после первого посещения». Не задан — ссылок нет |
| `space` | нет | Площадка клуба. Не задана — подвала со ссылками нет |
| `marquee` | нет | Тексты бегущих строк, до двух: верхняя и нижняя |
| `warmup` | нет | Игра-разминка: блок «Разминка» на главной с кнопкой «Играть». Не задана — блока нет |

`about` и `routine` — списки, даже когда абзац один. Строка вместо списка
отвергается при загрузке: YAML отдал бы её посимвольно, и страница показала бы
абзацы из одной буквы.

`facts` и `rules` — списки карточек, у каждой обязательны оба поля: `label` —
короткий заголовок, `text` — строка пояснения. Карточка без одного из них
отвергается при загрузке с ошибкой, которая называет поле и номер карточки:
пустая карточка на странице выглядит сломанной.

```yaml
facts:
  - label: Только очно
    text: Трансляций и записей нет — всё происходит в комнате
rules:
  - label: Разбираем вслух
    text: Это не лекция — главу берут по частям, и объясняют её разные люди
```

### Место

Место хранится по частям, а не строкой: сайту нужны две формы. Короткая —
площадка и комната, она стоит в лентах. Полная — здание, улица, этаж, комната,
город, по ней место находят те, кто едет впервые. Незаполненное поле выпадает
из строки целиком.

```yaml
place:
  venue: хакспейс s4m.space   # да, площадка: её называют в короткой форме
  building: Дом77             # да
  room: комната 413           # да
  street: Ленинградская 77    # нет
  floor: 4 этаж               # нет
  city: Самара                # нет
  map: https://2gis.ru/...    # нет, карточка места на карте: адрес на «О клубе» ведёт туда
```

`space` — это площадка, в которой живёт клуб:

```yaml
space:
  name: s4m.space              # обязательно
  site: https://s4m.space/
  channel: https://t.me/s4m_space
  chat: https://t.me/+инвайт   # общий чат площадки
  thread: https://t.me/c/…/…   # ветка клуба внутри этого чата
```

`warmup` — игра-разминка перед встречей. Сайт её у себя не держит: игра живёт
по своему адресу, кнопка «Играть» ведёт туда. Если раздел задан, обязательны все
три поля; адрес строкой вместо раздела отвергается при загрузке.

```yaml
warmup:
  name: Тыжархитектор          # название игры
  lead: "Карточный тренажёр по архитектуре: тянешь проблему системы — подбираешь решение"
  url: https://shvechkova.github.io/tyzharchitector/
```

Фраза в `lead` одна: шаги и правила игры на главную не выносятся. Двоеточие с
пробелом внутри фразы требует кавычек.

Перечня форматов в данных нет: раздел «О клубе» собирает его из встреч, которые
уже прошли. Чтобы формат появился на сайте, его нужно проставить встрече полем
`format`, а встреча должна состояться.

## books

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `id` | да | Идентификатор, попадает в адрес страницы |
| `number` | да | Номер книги. Задаёт порядок, в том числе у книг без встреч |
| `title`, `author` | да | Название и автор |
| `short_title` | нет | Короткое название для подписей в одну строку: карточки споров и кнопки встреч на главной. Не задано — берётся `title` |
| `status` | да | `voting`, `queued`, `reading`, `closed`, `dropped` |
| `chapters` | да | Оглавление по порядку. Номер главы — её позиция, с единицы |
| `taken_chapters` | нет | Номера глав, взятых в чтение. Не задано — взяты все |
| `period` | нет | «весна 2025». Для книг, встречи по которым не записаны |
| `notes_url` | нет | Конспект книги целиком |
| `cover` | нет | Обложка: путь внутри `app/web/static`, например `covers/brooks.jpg`. Нет — на её месте плашка с названием и автором |
| `close_note` | нет | Чем закончили. У закрытых и дропнутых |
| `takeaways` | нет | Выводы клуба списком |

У главы: `title` и необязательный `notes_url`.

`taken_chapters` нужен для выборочного чтения: «читаем не книгу, а вот эти
главы». Прогресс считается от взятых глав, а не от всего оглавления.

## meetings

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `id` | да | Идентификатор, попадает в адрес страницы |
| `date` | да | `ГГГГ-ММ-ДД` |
| `time`, `place` | нет | Не заданы — берутся из `club`. `place` задаётся теми же полями |
| `host` | нет | Ведущий |
| `book` | нет | `id` книги. Есть — у встречи книжная часть |
| `chapters` | нет | Разобранные главы: `{number, outcome}` |
| `format` | нет | Формат второго часа: `{name, note}` |
| `title` | если нет `book` | Собственное название встречи |
| `announce` | нет | Пункты анонса |
| `outcome` | нет | Итоги: три тезиса, цитата и полная форма — см. ниже |
| `topics` | нет | Темы встречи. Тема, совпавшая с названием или синонимом понятия словаря, ведёт в словарь — см. «Словарь» |
| `links` | нет | Ссылки: `{title, url}` |
| `images` | нет | Картинки встречи: `poster` и `recap` — см. ниже |

`outcome` у главы встречи — `closed` (закрыли), `carried` (перенесли) или
`planned` (ещё не разбирали). Не указан — значит `planned`: так пишется план
предстоящей встречи.
Перенесённая глава пройденной не считается, пока её не закроют на другой встрече.
Перечень глав не обязан идти подряд.

### Итоги встречи

Итоги бывают в двух формах, и обе необязательны. Три тезиса и цитата — короткая
выжимка: её показывает раздел «Сейчас». Полная форма — итоги так, как они ушли
постом в канал: её показывает страница встречи под тезисами.

| Поле | Что это |
| --- | --- |
| `agreed` | С чем согласились |
| `argued` | О чём спорили |
| `taken` | Что забираем |
| `quote` | Цитата вечера: `{text, chapter}` |
| `lead` | Вступление, абзац строкой |
| `by_chapter` | «О чём говорили по главам»: список пунктов |
| `debates` | «Главные споры»: список пунктов того же вида |
| `aside` | «Заодно уходили в…», строкой |
| `verdict` | Общий итог, абзац строкой |

Пункт `by_chapter` и `debates`:

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `text` | да | Текст пункта |
| `heading` | нет | Заголовок пункта, «Оценка сроков» |
| `chapters` | нет | Номера глав списком, `[6, 7]`. На странице стоят номером перед пунктом |

```yaml
outcome:
  agreed: …
  lead: …
  by_chapter:
    - { chapters: [8], heading: Оценка сроков, text: … }
    - { heading: Бюджеты, text: … }        # без глав
    - { chapters: [6, 7], text: … }        # без заголовка
  debates:
    - { heading: Блок-схемы, text: … }
  aside: …
  verdict: …
```

Пункты показываются в том порядке, в каком записаны. Незаписанная часть на
странице не оставляет пустого заголовка. Номера глав в пунктах проверяются так
же, как разобранные главы: глава должна быть в книге встречи, а у встречи без
книги номеров глав в итогах быть не может.

Участников в текстах итогов по имени не называют: сайт индексируется
поисковиками. Пишут безлично — «одни считают…». Имя остаётся только в `host`.

### Картинки встречи

У встречи может быть две картинки: афиша, с которой её анонсировали, и
карточка итогов. Обе необязательны.

```yaml
images:
  poster: { src: meetings/m-2026-10-21-poster.jpg, alt: … }   # афиша
  recap:  { src: meetings/m-2026-10-07-recap.jpg,  alt: … }   # карточка итогов
```

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `src` | да | Путь внутри `app/web/static`: `meetings/<id встречи>-poster.jpg` или `-recap.jpg` |
| `alt` | да | Подпись для тех, кто картинку не видит. Пересказывает текст на картинке |

Подпись обязательна, хотя у обложки она собирается сама: на афише и карточке
есть текст, которого больше нигде на странице нет, например цитата вечера
крупно. Картинка без подписи отвергается при загрузке.

До встречи на её странице стоит афиша. После встречи — карточка итогов, а если
её нет, то афиша. Эта же картинка уходит в карточку для пересылки ссылки
вместо логотипа.

Файлы — JPEG 1080×1350 (4:5) весом до 300 КБ. Исходники 2160×2700 ужимаются
один раз перед тем, как лечь в `static/meetings/`: сайт показывает картинку
шириной до 760 точек, а пересылке хватает 1080.

## Словарь

Понятия клуба лежат отдельным файлом рядом с данными: `glossary.yaml` рядом с
`club.yaml`, `glossary.example.yaml` рядом с `club.example.yaml` — имя
`glossary` и те же расширения. Переменная `CLUB_GLOSSARY` задаёт другой путь.
Нет файла — словарь пуст, а сайт работает: темы встреч стоят текстом.

```yaml
terms:
  - id: conway-law                 # якорь на странице словаря: /glossary#conway-law
    name: Закон Конвея
    aliases: [Conway's law]        # тема находит понятие и по синониму
    summary: >                     # одна-три фразы: подсказка у темы и карточка
      Система повторяет структуру общения в организации, которая её делает.
    article: https://github.com/…/topics/….md   # длинная статья, если есть
    chapters:                      # где понятие разобрано в конспектах
      - { book: brooks-mythical-man-month, chapter: 10 }
    related: [two-pizza-team]      # id других понятий словаря
```

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `id` | да | Строчная латиница, цифры и дефис. Стоит в адресе: `/glossary#conway-law` |
| `name` | да | Название понятия, как его показывает словарь |
| `summary` | да | Определение в одну-три фразы простым русским. Им же подсказка у темы встречи |
| `aliases` | нет | Синонимы списком: английское название, сокращение, другая форма |
| `article` | нет | Адрес длинной статьи, обычно `topics/*.md` репозитория конспектов |
| `chapters` | нет | Главы конспектов: `{book, chapter}`, `book` — id книги, `chapter` — номер главы |
| `related` | нет | id связанных понятий: на странице словаря ведут на их карточки |

Тема встречи находит понятие, если совпадает с его `name` или одним из
`aliases`, без учёта регистра и разницы «ё» и «е». Тема без понятия — не
ошибка: словарь — справочник, а не обязательный список тем. Если тема и
понятие называются по-разному, добавьте тему в `aliases`, а не новое понятие.

Адрес главы в словаре не пишется: подпись «книга, гл. N» и ссылка берутся из
главы в `books`. Нет у главы `notes_url` — подпись стоит текстом.

Встреч по понятию словарь не перечисляет.

## Что проверяется при загрузке

- В состоянии `reading` — не больше одной книги.
- `status` — из известного набора.
- Даты встреч разбираются как даты, идентификаторы не повторяются.
- У встречи без `book` есть `title`.
- `chapters` встречи указаны только вместе с `book` и ссылаются на существующие
  главы этой книги. То же — с номерами глав в пунктах итогов.
- У пункта итогов есть `text`.
- У картинки встречи есть `src` и `alt`, а в `images` нет ролей, кроме `poster`
  и `recap`.
- `taken_chapters` ссылаются на существующие главы.
- Поля `club.topic_notes` нет: адрес статьи о понятии задаётся в словаре.
- В словаре: id — строчная латиница, цифры и дефис; id, названия и синонимы не
  повторяются, регистр и «ё» не в счёт; у понятия есть `summary`; книга и номер
  главы в `chapters` есть в данных клуба; `related` ссылается на существующие
  понятия, но не на само понятие.
