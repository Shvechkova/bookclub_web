# Грабли

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Файл, записанный через heredoc в Bash, приходит искажённым: `SyntaxError: unterminated f-string literal` (вместо двух символов «обратный слэш» и «n» стоит настоящий перевод строки) или сама команда падает с `unexpected EOF while looking for matching` при одиночной кавычке в содержимом | Содержимое heredoc не доходит до интерпретатора буквально даже при закавыченном разделителе: обратные слэши теряются, одиночные кавычки ломают разбор команды | Не записывать через heredoc содержимое с кавычками и escape-последовательностями — использовать инструмент Write. Проверка искажения: `sed -n '<N>p' файл | cat -A` покажет `$` там, где ожидался литерал |
| YAML падает с `mapping values are not allowed here` на строке, которая выглядит обычным текстом | В незакавыченном значении есть двоеточие с пробелом — YAML принимает его за вложенный словарь | Заключать такие значения в кавычки: `close_note: "Бросили на второй главе: язык оказался неподъёмным."` Описано в `data/README.md` |
| В списке на странице вместо строки появился словарь вида `{'Вход свободный': 'без регистраций'}`, ошибки при загрузке нет | Двоеточие с пробелом внутри незакавыченного элемента YAML-списка: элемент разобрался как вложенный словарь, а `str()` его молча напечатал | Брать такие строки в кавычки. Загрузчик теперь отклоняет вложенные структуры в списках строк и называет причину — `app/data/loader.py`, функция `_texts` |
| Переменная окружения со значением, похожим на путь (`SITE_BASE=/bookclub_web`), приезжает в программу как `C:/Program Files/Git/bookclub_web` | Git Bash на Windows подставляет пути: значение, начинающееся со слэша, он считает путём MSYS и разворачивает в windows-путь | Ставить `MSYS_NO_PATHCONV=1` перед командой либо передавать значение без ведущего слэша — код сам его добавит. На Linux, в том числе в GitHub Actions, подстановки нет |
| `openspec init` не создаёт ни `CLAUDE.md`, ни `openspec/project.md` — их ищут по старым примерам из документации | В версии 1.13 инструкции раздаются скиллами и слэш-командами в `.claude/`, а контекст проекта лежит в `openspec/config.yaml` | Контекст проекта и правила по артефактам писать в `openspec/config.yaml` (секции `context`, `rules`, `operations`). Файлы в `.claude/` перегенерируются командой `openspec update`, свои правки там не переживут обновления |
| `pip install -e ".[dev]"` на свежем Python падает на сборке PyYAML: `Microsoft Visual C++ 14.0 or greater is required` | Готового колеса PyYAML под новый Python ещё нет, и pip собирает его из исходников вместе с расширением на C, а компилятора на машине нет | Ставить с `PYYAML_FORCE_LIBYAML=0`: PyYAML соберётся без расширения, на чистом Python. Сайту скорости хватает, `yaml.safe_load` тот же. Когда колесо выйдет, переустановка возьмёт его сама |
