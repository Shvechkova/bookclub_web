# Design

## Context

Разметку для поиска уже складывает `app/web/seo.py`: описание страниц, сведения о
клубе и событие встречи. Абсолютные адреса строятся из настройки `SITE_URL` и
`SITE_BASE`; без адреса сайта канона, карточки и schema.org нет — это правило
остаётся. Заголовки страниц пока задаются блоком `title` в каждом шаблоне.
Сайт выгружается в статику и живёт на GitHub Pages: каждая страница — папка с
`index.html`.

Аудит выгрузки с `SITE_URL=https://club.example.org`:

| Что | Было |
|---|---|
| `<html lang="ru">`, `og:locale`, `og:site_name`, `twitter:card` | есть |
| Заголовки | общие у разделов, «Встреча #1» у двух встреч |
| Описания | уникальны; на главной 79 знаков |
| Канон, карта сайта | `/history` без слеша — на Pages это переадресация |
| `og:type` | `website` везде |
| `og:image` | логотип 504×473 без размеров |
| `Organization` | без адреса и города; в `sameAs` ссылки площадки |
| `Event` | время без пояса, адрес строкой, нет окончания и картинки |
| `Book`, `DefinedTermSet`, `WebSite`, `BreadcrumbList` | нет |
| 404, иконки, манифест, цвет темы | нет; иконка — логотип 240 КБ |
| `h1` | ровно один на каждой странице |
| `alt` | у обложек и картинок встреч есть; логотипы — пустой `alt` при подписи ссылки |
| Шрифты | `preconnect` и `display=swap` есть |

## Goals / Non-Goals

**Goals:**
- По каждой странице поисковик видит свой заголовок и описание, собранные из
  данных, и разметку schema.org того, что на ней показано.
- Канон, карта сайта и разметка указывают адрес, который отвечает 200.
- Ссылка в телеграме разворачивается в большую карточку на любой странице.

**Non-Goals:**
- Аналитика и счётчики.
- `lastmod` в карте сайта — см. решение ниже.
- Смена внутренних ссылок на форму со слешем.
- Отдельная страница на каждое понятие словаря.

## Decisions

### Заголовки и описания собирает `seo.py`, шаблоны их только выводят

Маршрут передаёт `title` в контекст, `base.html` выводит его в `<title>` и
`og:title`. Блоки `title` в шаблонах убираются: заголовок нужен и разметке, и
тестам, а из шаблона его не достать.

Заголовок подбирается функцией `fit`: из нескольких вариантов от полного к
краткому берётся первый, что помещается в 65 знаков. Название «Фундаментальный
подход к программной архитектуре» с авторами и клубом не влезает, и обрезать его
посреди слова хуже, чем отбросить хвост «· Кабанья Читальня»: имя сайта
поисковики и так показывают рядом.

- Главная: «Кабанья Читальня — IT-книжный клуб в Самаре» — как было, город уже
  в нём.
- Книга: «‹Название›», автор — обсуждение по главам · клуб → без автора → без
  клуба. «Обсуждение» — слово, с которым книгу ищут.
- Встреча: «‹заголовок встречи› — обсуждение ‹дата›» с клубом и без; дата
  делает заголовок единственным, номер «#1» из заголовка уходит — он свой у
  каждой книги и снаружи путает. Номер остаётся в описании.
- Разделы называют, что в них, и город: «Полка: книги и итоги встреч IT-книжного
  клуба», «Словарь: IT-понятия со встреч клуба», «О клубе» берёт
  `about_title` («Первый IT-книжный клуб Самары»).

Описание главной дописывается слотом и площадкой — по ним клуб ищут в городе.
Описание встречи — номер, дата, время, место, город, главы и первая фраза итогов
или анонса. Книги — автор, что с книгой сейчас и город. Словаря — число понятий
и первые из них по алфавиту. Всё режет существующая `shorten`.

Уникальность проверяет тест по всей выгрузке: заголовки и описания всех
страниц попарно различны.

### Канон со слешем, внутренние ссылки — без изменений

GitHub Pages отдаёт `history/index.html` по `/history/`, а `/history`
переадресует на него. Канон, `og:url`, адреса schema.org и карта сайта берут
форму со слешем (`seo.page_url`), главная — `/`. Внутренние ссылки остаются как
есть: сервер разработки знает маршруты без слеша и на `/history/` сам
переадресовал бы обратно; поисковик по одной переадресации всё равно приходит к
канону. Менять сотни ссылок и маршрутов ради этого — дороже выгоды.

### Карточка пересылки: тип страницы, размеры, карточка клуба

`og:type` — `book` на странице книги, `website` на остальных. Для встречи
подходящего типа в Open Graph нет: `article` означает авторскую публикацию, а
событие описывает schema.org. У картинки — `og:image:width`, `og:image:height`
и `og:image:alt`: телеграм и ВКонтакте без размеров иногда показывают маленькую
карточку.

Логотип 504×473 для `summary_large_image` не годится: его обрезают по краям.
Новая карточка `static/og-card.jpg` 1200×630, 85 КБ, в стиле афиш клуба —
голубая и пурпурная полосы, кабан, надпись логотипа, манифест. Собрана один раз
снимком HTML в Playwright из `logo-mark.png` и `logo-words.png`; Pillow в
проекте нет, а тянуть его ради одной картинки не нужно. Картинка встречи
(1080×1350) по-прежнему важнее карточки клуба.

### schema.org — отдельными блоками, связанными через `@id`

Каждый узел — свой `<script type="application/ld+json">`: так существующие
проверки «блок с `@type` Organization» работают без разбора `@graph`, а
поисковики связывают блоки страницы по `@id`. Список блоков собирает маршрут
из функций `seo.py`, шаблон выводит его циклом.

- `Organization` (`#club` на главной) — на всех страницах: логотип, описание,
  `address` и `location` — площадка с почтовым адресом, `areaServed` — город.
  `sameAs` — только чат клуба: сайт, канал и чат площадки — другая организация,
  `sameAs` для неё означал бы «это мы».
- `WebSite` — только на главной, `inLanguage: ru`, издатель — клуб.
- `Event` — встреча: `startDate` и `endDate` со смещением пояса клуба (через
  `zoneinfo`, длительность — `duration_minutes`), `location` — `Place` с
  `PostalAddress` и картой, `organizer` — ссылка на клуб, `image`,
  `description`, `isAccessibleForFree`, `offers` с ценой 0 ₽ (Google просит
  `offers` у события, бесплатный вход — это цена 0), `eventStatus` —
  `EventScheduled`, `workFeatured` — книга встречи.
- `Book` — название, авторы (`Person` по запятой в строке автора), обложка,
  адрес. ISBN в данных нет — поля нет.
- `DefinedTermSet` — все понятия словаря: `name`, `description`,
  `alternateName` для синонимов, `url` с якорем понятия.
- `BreadcrumbList` — внутренние страницы: клуб → раздел → книга → встреча.

Страна в адресе — константа `RU`: в данных её нет, а клуб очный и самарский.

### Часовой пояс — `zoneinfo` и пакет `tzdata`

Смещение Самары считается из `club.timezone`, а не зашивается `+04:00`: пояс в
данных уже есть, и при переезде клуба его не придётся искать в коде. В Windows
своей базы поясов нет, поэтому в зависимости добавлен `tzdata`.

### `lastmod` в карте сайта не пишется

Достоверно вывести дату правки страницы не из чего. Дата встречи занижает её:
итоги дописывают через дни после встречи. Время изменения файла данных на CI
равно времени checkout — каждая выкатка объявила бы все страницы изменёнными, и
выгрузка перестала бы быть повторяемой. Google при неверном `lastmod`
перестаёт доверять ему на всём сайте, Яндекс поле не требует. Без `lastmod`
поисковики обходят карту по своему расписанию — для сайта в полтора десятка
страниц этого хватает.

### Страница 404 — шаблоном сайта

`not_found.html` наследует `base.html`: шапка, подвал и ссылка на главную. В
ней `<meta name="robots" content="noindex">` и нет канона, карточки и
schema.org. Сервер разработки отвечает ею на любой 404, выгрузка пишет её в
`404.html` — GitHub Pages отдаёт этот файл на любой неизвестный адрес. Ссылки в
ней абсолютные с `SITE_BASE`, поэтому работают с любой глубины адреса.

### Иконки и манифест

Из `logo-mark.png` собраны `favicon.ico` (16, 32, 48 внутри — Яндекс берёт
`.ico`), `favicon-32.png`, `apple-touch-icon.png` 180, `icon-192.png`,
`icon-512.png`. На квадратных 180–512 под кабаном чёрный фон: iOS заливает
прозрачное своим цветом. `favicon.ico` выгрузка кладёт ещё и в корень сайта —
его запрашивают без ссылки. Манифест `manifest.webmanifest` собирается
маршрутом из данных клуба (имя, цвет), адреса иконок в нём — относительно
`SITE_BASE`. `theme-color` — `#0a0a0a`, фон сайта. Шапка по-прежнему грузит
исходный логотип — уменьшать его здесь не стали.

### Подтверждение прав — необязательные переменные окружения

`create_app` получает `verification` — словарь «имя мета-тега → значение»;
`seo.verification_from_env` собирает его из `YANDEX_VERIFICATION` и
`GOOGLE_SITE_VERIFICATION`. Пустые не выводятся. Теги не зависят от
`SITE_URL`: в них нет адресов. Выкатка передаёт одноимённые переменные
репозитория.

### Ссылки между страницами

Встреча уже ведёт на книгу и понятия словаря, книга — на свои встречи, полка —
на всё. Ссылки словаря на главы ведут в конспекты: дешёвых пробелов, которые
стоило бы закрывать здесь, нет.

## Risks / Trade-offs

- [`robots.txt` в папке проекта] на `owner.github.io/bookclub_web/` файл лежит не
  в корне домена и поисковиками не читается → карту сайта добавляют в
  Вебмастере вручную; со своим доменом всё работает само.
- [Карточка клуба — картинка с текстом] при смене манифеста её надо пересобрать
  → в `design.md` записано, как она собрана; данные меняются редко.
- [Заголовок без названия клуба] у длинных книг хвост «· Кабанья Читальня»
  отбрасывается → поисковики показывают имя сайта отдельно.
