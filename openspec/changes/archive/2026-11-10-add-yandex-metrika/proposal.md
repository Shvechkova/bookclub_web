# Proposal

## Why

У сайта клуба нет статистики: не видно, сколько людей заходит, откуда они приходят (канал, чат, поиск) и какие страницы читают. Счётчик в Яндекс.Метрике уже заведён (№ 114153922), осталось поставить его код на страницы.

## What Changes

- Каждая страница сайта, включая страницу «не найдено», несёт код счётчика Яндекс.Метрики, если при сборке задан номер счётчика.
- Номер счётчика задаётся переменной окружения `YANDEX_METRIKA_ID`, по образцу `YANDEX_VERIFICATION`. При выкатке берётся одноимённая переменная репозитория.
- Без переменной кода счётчика на страницах нет: локальный запуск, тесты и чужие форки посещений в статистику не добавляют.
- Настройки счётчика — как в коде, который выдала Метрика: вебвизор, карта кликов, учёт внешних ссылок, точный показатель отказов.
- В README появляется раздел о том, как включить счётчик.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `club-site`: новое требование — страницы несут счётчик посещений, когда задан его номер.

## Impact

- `app/web/seo.py` — чтение номера счётчика из окружения.
- `app/web/app.py`, `app/web/export.py`, `app/web/asgi.py` — передача номера в шаблоны.
- `app/web/templates/base.html` — код счётчика.
- `.github/workflows/pages.yml` — переменная `YANDEX_METRIKA_ID` в шаге выгрузки.
- `README.md` — раздел о счётчике.
- `tests/test_seo.py` — проверки.
- Внешняя зависимость: страницы начинают грузить скрипт с `mc.yandex.ru`. Вебвизор записывает действия посетителей; данные уходят в Яндекс.
- Руками после выкатки: завести переменную репозитория `YANDEX_METRIKA_ID=114153922` и перезапустить выкатку.
