# Design

## Context

Сайт — статическая выгрузка на GitHub Pages; все страницы наследуют `app/web/templates/base.html`. Коды подтверждения прав уже приходят из окружения: `seo.verification_from_env` → `create_app(verification=…)` → шаблон, а при выкатке `pages.yml` подставляет переменные репозитория. Счётчик идёт тем же путём.

## Goals / Non-Goals

**Goals:**

- Посещения боевого сайта видны в Метрике.
- Локальный запуск и тесты статистику не портят и в сеть за счётчиком не ходят.

**Non-Goals:**

- Цели и события (клики по «чат читальни», переходы на конспекты) — отдельным изменением, когда появятся первые данные.
- Плашка согласия на cookies и страница политики конфиденциальности.
- Другие счётчики (Google Analytics и т. п.).

## Decisions

**Номер счётчика — из переменной окружения `YANDEX_METRIKA_ID`, а не константой в шаблоне.** Счётчик с номером в коде срабатывал бы при локальном запуске, в тестах с браузером (Playwright) и на форках. Номер не секрет, поэтому это переменная репозитория, а не секрет — как `YANDEX_VERIFICATION`. Альтернатива — константа плюс проверка `location.hostname` в скрипте — отвергнута: домен пришлось бы дублировать в шаблоне.

**Чтение — отдельной функцией в `seo.py` (`metrika_id_from_env`), значение принимается только из цифр.** Номер подставляется внутрь `<script>` и в адрес; проверка `str.isdigit()` закрывает подстановку произвольного текста. Нецифровое значение даёт `None`, то есть счётчика нет. В `create_app` и `export` добавляется параметр `metrika_id: str | None = None` рядом с `verification`.

**Код счётчика — в `base.html`, в конце `<head>`, под условием `{% if metrika_id %}`.** Текст — тот, что выдала Метрика, с номером из переменной; параметры `ssr`, `webvisor`, `clickmap`, `ecommerce`, `referrer`, `url`, `accurateTrackBounce`, `trackLinks` сохраняются как есть. `<noscript>` с картинкой в `<head>` недопустим по HTML, поэтому он ставится первым в `<body>`.

**`404.html` получает счётчик без отдельных усилий:** страница «не найдено» наследует тот же базовый шаблон.

## Risks / Trade-offs

- [Вебвизор записывает действия посетителей и ставит cookies; по 152-ФЗ для этого ждут политику обработки данных и уведомление] → на сайте нет форм и входа, записывать особо нечего; если понадобится, вебвизор выключается в настройках счётчика в интерфейсе Метрики без правки кода, а политика и плашка — отдельное изменение.
- [Блокировщики рекламы режут `mc.yandex.ru`] → цифры будут занижены; для клуба это приемлемо.
- [Переменную репозитория забыли завести] → сайт выкатывается без счётчика, ничего не ломается; шаг описан в README и в задачах.

## Migration Plan

1. Выкатить код.
2. Завести переменную репозитория `YANDEX_METRIKA_ID=114153922` (Settings → Secrets and variables → Actions → Variables).
3. Перезапустить выкатку и проверить счётчик в Метрике («Проверить счётчик» или открыть сайт с `?_ym_debug=2`).

Откат — удалить переменную и перезапустить выкатку.
