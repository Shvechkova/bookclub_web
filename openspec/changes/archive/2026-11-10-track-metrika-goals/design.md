# Design

## Context

Код счётчика стоит в `base.html` и появляется только при заданном `metrika_id`. Сайт статический (GitHub Pages), без сборщика скриптов. Ссылки, которые надо отметить, разбросаны по пяти шаблонам. В счётчике 114153922 целей нет; токен с правами на счётчик лежит в пользовательской переменной окружения `YM_TOKEN`.

## Goals / Non-Goals

**Goals:**

- Видеть в Метрике конверсии в четыре действия: календарь, чат, конспект, игра.
- Один обработчик на сайт, без правки каждой ссылки скриптом.

**Non-Goals:**

- Цели на посещение страниц (их Метрика заводит без кода).
- Отчёты из API и выгрузка статистики.
- Хранение токена в репозитории или в переменных выкатки.

## Decisions

**Пометка ссылок атрибутом `data-goal`, один делегированный обработчик в `base.html`.** Обработчик слушает клики на документе и для ближайшей ссылки с `data-goal` вызывает `ym(id, 'reachGoal', goal)`. Альтернатива — `onclick` у каждой ссылки: дублирует номер счётчика в пяти шаблонах.

**Атрибут `data-goal` стоит всегда, обработчик — только со счётчиком.** Атрибут ничего не делает сам по себе, а шаблоны не обрастают условиями. Без счётчика нет и обработчика.

**Переход не задерживается.** Ссылки открываются в новой вкладке или уходят на внешние адреса; `reachGoal` отправляется через `sendBeacon` самой Метрикой, ждать его не нужно.

**Цели заводит скрипт `scripts/metrika_goals.py` через Management API.** Тип цели `action` с условием `exact` по идентификатору. Скрипт сначала читает существующие цели и создаёт только недостающие — повторный запуск безопасен. Токен читается из `YM_TOKEN` и нигде не печатается.

## Risks / Trade-offs

- [У токена может не быть права записи] → скрипт сообщит об ошибке 403; тогда цели заводятся руками в кабинете по таблице из README.
- [Блокировщики рекламы режут Метрику] → цели недосчитываются так же, как визиты; поведение ссылок от этого не зависит.
