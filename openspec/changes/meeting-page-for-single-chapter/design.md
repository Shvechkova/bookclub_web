# Design

## Context

Глава встречи в модели — пара «номер, исход» (`DiscussedChapter`). Страница встречи получает из представления только главы книги по номерам (`chapters_of_meeting`), без данных самой записи встречи, поэтому пометку показать негде. Заголовок «По главам» и номер у пункта зашиты в `meeting.html`. Строка «берём главу N» на «Сейчас» и ссылки на встречи в оглавлении книги собираются в `now.html` и `book.html`.

## Goals / Non-Goals

**Goals:**

- Страница встречи читается одинаково хорошо при одной главе и при восьми.
- Одна строка данных позволяет сказать, какая часть главы взята.
- Встречи по Бруксу выглядят как раньше, рабочие данные править не нужно.

**Non-Goals:**

- Разделы глав в оглавлении книги и прогресс внутри главы.
- Переименование поля `by_chapter` в данных.
- Перестройка итогов вокруг тем вместо глав.
- Изменение подсчёта пройденных глав.

## Decisions

**Пометка — свободная строка `part` у главы встречи.** `{ number: 2, outcome: carried, part: "до раздела «Масштабируемость»" }`. Альтернатива — список разделов у главы в `books` и ссылки на них из встречи: даёт прогресс внутри главы, но требует вести разделы для 14 глав и новые проверки. Пока прогресс внутри главы никому не нужен, строка дешевле.

**`part` не связана с исходом.** Поделённую главу записывают как `carried` на первой встрече и `closed` на второй, пометка только поясняет. Проверки вида «у `carried` обязана быть пометка» нет: по Бруксу главы переносили без пометок.

**Представление отдаёт главу встречи вместе с пометкой.** `chapters_of_meeting` возвращает пары «глава книги + пометка», шаблоны берут пометку оттуда же, откуда название. Для оглавления книги пометка добавляется к уже существующей связке «глава — встречи». Альтернатива — искать пометку в шаблоне по номеру главы: логика уезжает в шаблон.

**Заголовок блока выбирается по числу глав встречи, а не по пунктам.** Больше одной главы — «По главам» и номера у пунктов; иначе — «О чём говорили» без номеров. Число глав встречи известно всегда, а пункты могут быть без номеров вовсе. Поле в данных остаётся `by_chapter`: переименование задело бы все записанные встречи, скилл и README ради подписи.

**Одна глава — строка, несколько — прежний список.** Заголовок раздела «Разобрали» / «Разбираем» остаётся в обоих случаях. Ссылка «конспект» и пометка добавляются в оба вида.

**Цитата вечера сохраняет подпись «глава N».** Она стоит одна и не повторяется, как номера у пунктов.

## Risks / Trade-offs

- [Свободный текст пометки пишут по-разному: «до…», «первая половина», «разделы 1–2»] → README даёт образец формулировки; сайт показывает текст как есть.
- [Пометки двух встреч могут не сходиться между собой] → не проверяется: это текст для читателя, а не данные для расчёта.
- [Тесты страницы встречи завязаны на «По главам»] → существующие тесты переводятся на встречу с несколькими главами, для одной главы добавляются новые.
